# 脉冲学习法（Pulse Learning Method）

一种解决"学习动力不足"问题的结构化学习框架。核心思想：将学习任务转化为一个**有紧迫感的限时挑战**，配合严格量化验收和奖章激励，提升学习动机与完成率。

## 与 self-directed-learning-framework 的关系

本 skill 是学习**动力层**框架，聚焦于"怎么让自己行动起来并保持专注"；skill `productivity:self-directed-learning-framework` 是学习**方法论层**框架，聚焦于"怎么高效地学"。两者可组合使用：脉冲法负责评级+限时+激励，SRL循环负责实际学习过程的执行。

## 核心流程

```mermaid
flowchart TD
    A[用户提出学习需求] --> B{是"继续学"还是"新学"?}
    B -->|新学| C{Emma反推确认}
    C -->|确认值得学| D[任务评级 1-3级]
    C -->|确认不值得| Z[建议放弃或换方式]
    B -->|继续学| E[查看历史进度 + 确认当前目标]
    E --> D
    D --> F[设定脉冲学习时间]
    F --> G[用户开始学习]
    G --> H[用户报完成/超时]
    H --> I[量化验收]
    I -->|通过| J[🏅 颁发脉冲奖章]
    I -->|未通过| K[指出不足，建议补学]
    H -->|超时| L[❌ 不颁奖章+分析原因]
```

## 继续学习 / 中途恢复

当用户说"继续学X"/"接着学X"（而非从头开始新任务）时，流程自动进入恢复模式：

1. **查历史进度** — 通过 session_search 或成就记录簿查找之前学到哪了、当前阶段、已掌握内容
2. **确认当前目标** — 询问用户想接着哪个节点继续、这次的目标是什么
3. **跳过后直接评级定脉冲** — 跳过"为什么要学"的反推（因为上次已确认过），直接评估**剩余内容**的难度并设定脉冲时间
4. **验收范围收窄** — 验收只覆盖本次新增内容，不再重考已掌握的部分

> **恢复模式下的 反推确认 改为「目标对齐」：** 只问"这次你想攻克哪个部分？"和"这次学完打算用来解决什么？"，不做"值不值得学"的全流程评估。

## 阶段一：反推确认

用户提出学习需求后，**不要**直接给资料。先追问：

1. **为什么要学这个？** — 要解决什么具体问题？
2. **这个问题当前是否阻塞你？** — 紧迫程度
3. **投入这个时间值不值得？** — 有没有更低成本的替代方案（比如只看某几章、用现成工具等）

如果确认值得投入，进入评级。

## 阶段二：任务评级（三级）

评级从四个维度综合判断：
- **知识广度** — 涉及多少子领域/子技能
- **知识深度** — 需要理解底层原理还是够用就行
- **前置依赖** — 需要先学其他东西吗
- **用户基础** — 你在该领域的熟悉程度

### 1级任务（最小）
- 小知识点或单一技能模块
- 有基础，且不是完全零基础
- **脉冲时间建议：2h ~ 1天**
- 示例：
  - 系统学正则表达式
  - 学完 `pathlib` 完整用法
  - 掌握 `git rebase` 高级用法

### 2级任务（中等）
- 涉及多个子技能，有一定知识跨度
- 有周边基础，但需要系统化
- 肌肉记忆/实践积累需要时间
- **脉冲时间建议：3天 ~ 10天**
- 示例：
  - 掌握 Vim 编辑器日常高效使用
  - 系统学 SQL 从基础到窗口函数
  - 学完 Python asyncio 实战

### 3级任务（高难度）
- 全新领域，零基础或极弱基础
- 概念高度抽象，需要深层理解
- 涉及知识体系广泛，无法短期速成
- **脉冲时间建议：1周 ~ 4周**
- 示例：
  - 系统学习黑格尔哲学
  - 从零搭建 Django REST Framework 并部署
  - 系统学习 Linux 内核模块开发

> **评级方法：** Emma 根据四个维度综合评估，并将评估过程向用户透明展示，用户可以调整评级。

## 阶段三：设定脉冲学习时间

采用**自然时间窗口**（注意跨天任务要考虑用户每日有效学习时间）。

| 等级 | 参考脉冲时间 |
|------|------------|
| 1级 | 2小时 ~ 1天 |
| 2级 | 3天 ~ 10天 |
| 3级 | 1周 ~ 4周 |

设定原则：
- 时间要有**紧迫感**但不能**不切实际**
- 用户自己承诺时间窗口，双方确认
- 跨天任务：按每天~4-6h有效学习时间估算
- **Emma 给出建议时间后，主动问用户是否要调短或调长** — 用户对自己节奏的感知通常比预估准确
- 如果用户坚持比自己预估更短的时间，尊重用户判断（但提醒剩余题量）

### 材料准备时间

在设定脉冲时间之前，Emma 需要准备的**学习材料**（创建练习文件、搭建 dojo、找参考资料等）应在**脉冲计时开始前完成**，不占用用户的学习时间窗口。

- 若材料可以**几分钟内搞定**（如出几道实操题），可用 `delegate_task` 并行准备
- 若需要较长时间（创建项目脚手架、写多阶段练习），**先准备好再启动脉冲**
- 准备好后 push 到仓库，告知用户 `git pull` 即可开始
- 在脉冲执行过程中若发现材料有 Bug（如题目描述歧义、测试数据不合理），尽快修复后 push，并向用户说明

## 阶段四：量化验收（关键！）

严格、客观、可量化的验收标准，**避免60分也通过**。

### 按等级划分的验收方式

| 等级 | 验收方式 | 示例 |
|------|---------|------|
| 1级 | Emma出实操测试题，覆盖核心知识点，要求**全部通过** | 正则：出10道覆盖元字符/量词/分组/环视的题 |
| 2级 | 真实环境任务式验收 + 随机追问 | Vim：在编辑器中完成指定操作序列；SQL：出5道综合查询题 |
| 3级 | 结构化输出（总结/笔记/实现）+ 追问验证深度 | 黑格尔：输出500字框架性总结 + 回答Emma的3-5个追问 |

### 判定规则
- ✅ **通过** → 全部验收项达标（接近100%准确）
- ❌ **不通过** → 任何一项有明显错误/遗漏 → 指出不足，建议补学，不计为完成
- ⏰ **超时** → 截止时间前未报完成 → 不颁奖章，分析原因（任务过重/懈怠/干扰）

### 通过后
- 宣布"你达成了脉冲学习目标" ✅
- 记录成就，更新记录簿

### 未通过时
- 明确指出现有问题（如"第3题环视写错了"、"Vim宏部分明显生疏"）
- 给出针对性建议
- **推荐验收反馈格式（经过实战检验）：**
  1. ❌ **真正做错的题** — 逐题说明：实际输出 vs 期望输出、根因分析（回溯/边界条件/语法错误）、具体修复方法
  2. 🔶 **通过了但写得不好的题** — 指出虽然测试过了但模式脆弱/冗余/有副作用的写法，并展示更优方案
  3. 每个问题附一句话"为什么" + 一句"怎么改"，避免纯理论说教
- **不颁发奖章**

## 用户定级对齐流程

在新用户启用脉冲学习法初期，可执行模拟定级环节：

1. Emma 出若干不同领域/难度的任务
2. 对每个任务给出评级 + 详细理由（四维度分析）
3. 用户审核每一级，"过了"则通过，"不过"则说明应定X级及理由
4. 双方对齐评级标准后，正式开始使用

## 常见陷阱

| 陷阱 | 表现 | 对策 |
|------|------|------|
| 任务过大 | 脉冲时间设得太长，失去紧迫感 | 拆分为多个1-2级任务，分多次脉冲 |
| 任务过小 | 不值得走完整流程 | 直接学完即可，跳过脉冲流程 |
| 验收放水 | 过了70%就当通过 | 严格执行"全部通过"原则 |
| 脉冲时间太死 | 用户因突发事务超时，但实际学好了 | 区分"客观超时"和"懈怠超时"，前者可酌情调整 |
| 评级虚高 | 把1级评成2级，学习动力反而下降 | 严格按四维度矩阵，宁可偏低不偏高 |
| 恢复模式当新学 | 用户说"继续学"，仍从头反推+评级 | 自动识别恢复模式，查进度→收窄范围→直接定脉冲 |
| 材料有 Bug | 验收题描述歧义/测试数据缺陷，用户花时间排查材料而非学习内容 | 出题后自己先跑一遍验证，发现 Bug 及时修复并告知用户 |
| 修改材料覆盖用户答案 | 修复/优化练习文件时，patch 操作意外重置了用户填好的答案 | 改描述不动答案；必须动时先确认是否需要备份 |

## 触发条件

- 用户说"我想系统学X" / "我想掌握X" / "给我安排个学习计划"
- 用户说"继续学X" / "接着学X" / "上次学了一半继续"
- 用户提到对某个技能有学习动机但迟迟没行动
- 用户表示"学不下去" / "缺乏动力" 且提及具体学习任务
