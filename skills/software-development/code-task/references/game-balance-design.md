# 游戏数值设计 — 数据驱动平衡流程

> 适用场景：设计游戏经济、修炼曲线、消耗品定价、推演/锻造阈值、概率分布等数值相关功能。
> 本文件记录从代码提取真实曲线 → 计算玩家路径 → 迭代调优的完整 PM 工作流。

---

## 核心原则

**不做空想数值。** 每一次设计决策必须基于从代码中提取的实际公式计算，而非直觉或粗略估计。

---

## 标准工作流

### Phase 1：代码侦察 — 提取真实曲线

找到项目中控制数值的核心公式和常量：

```python
# 搜索目标（关键词随项目变化）：
# curve_*, CULTIVATION_*, threshold, RARITY_*, _calc_*, formula, INTERVAL
```

**典型输出：**
| 项 | 来源 |
|----|------|
| 修炼速度公式 | `realm_util.py:curve_cultivation()` / 经脉÷10² |
| 突破所需修为 | `realm_util.py:curve_cultivation(level)` = 280 × level² + 1 |
| 每tick间隔 | `CULTIVATE_INTERVAL = 30` 秒 |
| 境界映射 | `(level + 9) // 10` → 0=凡人…6=大乘 |
| 现有消耗阈值 | `RARITY_THRESHOLDS` 等 |

**写一个 Python 脚本**提取完整数值表（见下文模板）。

### Phase 2：多路径场景分析

不只看「平均」或「主力」路径。至少跑三条线：

| 路径 | 场景 | 目的 |
|------|------|------|
| 🔴 最差路径 | 伪灵根/最低初始属性/无加成 | 防止新手坐牢 |
| 🟢 最优路径 | 天灵根/满加成/全力优化 | 上限体验，检查是否会过强 |
| 🟡 中间路径 | 普通属性/部分加成 | 多数玩家的实际感受 |

**计算内容：**
- 到各时间节点的累计收益/消耗
- **刚突破大境界后剩多少资源**（这是用户最关心的盲区）
- 「要攒多久才够一次门槛」
- 「不做这个选择的话自然增长如何」

### Phase 3：门槛设计

**两条硬约束：**

| 约束 | 含义 | 检查方法 |
|------|------|---------|
| **境界锁** | 当前境界玩家到巅峰也攒不够下一境界的门槛 | 巅峰余额 < 下级门槛 |
| **可用性** | 刚突破到新境界后不至于是0资源，能很快用上 | 突破后余额 ≥ 门槛 × (70%-100%) |

**常见数值失误：**

> ❌ 用了累计总修炼量当分母 → 会远高于实际可支配余额（大部分已被突破消耗）
> ✅ 用突破后的实际余额 + 当前修炼速度来算

> ❌ 只算最优路径 → 伪灵根坐牢73分钟
> ✅ 先算最差路径再调低门槛，保证前期体验

> ❌ 门槛定在「刚好突破后掏不出」的尴尬位置
> ✅ 突破后余额刚好够一次，或者只需几分钟就能攒够

### Phase 4：迭代呈现

不要一次给死方案。用 **多旋钮** 风格呈现：

```
旋钮 1：练气门槛 — A. 200 / B. 500 / C. 1000
旋钮 2：筑基门槛 — A. 5K / B. 10K / C. 20K
…
→ 用户逐条回复 → Emma 按选择编译完整设计稿 → 确认 → 路由小弟
```

每次迭代附带**精算数据表**（多少分钟、多少tick、突破后余额），而不是纯观点。

## Python 脚本模板

```python
from utils.realm_util import curve_cultivation  # 替换为实际导入

def cumulative_to_level(n):
    """累计到 level n（不含 n 本身的突破花费）"""
    return sum(curve_cultivation(i) for i in range(n))

# 每境界巅峰时的真实余额（假设每次突破前多攒 X%）
EXCESS = 0.125  # 12.5% — 根据玩家行为调整
peak_balance = {}
for realm in range(1, 7):
    first = (realm - 1) * 10 + 1
    total_in_realm = cumulative_to_level(first + 9) - cumulative_to_level(first - 1)
    peak_balance[realm] = total_in_realm * EXCESS

# 检查每条约束
for threshold_value, tier in [(500,1), (10000,2), ...]:
    prev_peak = peak_balance[tier - 1]

    print(f"  门槛{threshold_value}: 境界锁{'✅' if prev_peak < threshold_value else '❌'} "
          f"可用性{'✅' if after_breakthrough_balance >= threshold_value * 0.7 else '❌'}")
```
